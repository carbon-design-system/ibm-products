## Summary

Starting with **Carbon v12**, the high-value components from
`@carbon/ibm-products` are being selectively migrated into the Carbon core
packages (`@carbon/react` and `@carbon/web-components`). This means:

- You will eventually install **one package** instead of two.
- Migrated components become first-class Carbon APIs, gaining v12 features
  (updated motion, rounded corners, new tokens) immediately.
- `@carbon/ibm-products` stays available but enters **minimal maintenance mode**
  after v12 ships — no new features or components will be developed there.
- A **one-time import-path change** is required for components that migrate.
  Codemods will be provided to automate this.
- Migrated components will be available in both **`@carbon/react`** and
  **`@carbon/web-components`**. Web Components ports are delivered as follow-up
  work per component and may not land simultaneously with the React
  implementation at v12.

## Why is this happening?

`carbon-for-ibm-products` was built upon the foundational components of Carbon
Core, extended with additional components, styling, and guidance crafted
specifically for software product use cases, it is not a replacement for Core,
but a specialized layer on top of it. That separation was useful early on, but
it now creates friction:

- **Two packages to install.** Adopters must manage both `@carbon/react` and
  `@carbon/ibm-products` to get the full component set.
- **Duplicated infrastructure.** Two CI pipelines, two Storybooks, two release
  workflows — maintenance overhead with no consumer benefit.
- **Slower v12 adoption.** Components in a separate repo cannot easily consume
  in-flight monorepo changes, lengthening the feedback loop.
- **Visibility across squads.** PRs and issues from different teams cannot
  cross-reference when work is split across two repos.

## What happens to this package?

| Phase         | What it means for you                                                                                                                                                                                                                                      |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Now → v12** | Everything continues to work. Components are being migrated internally but not yet exported from `@carbon/react`. No changes required on your side. Migrated components will be published from release branch (alpha releases) early on with v12 features. |
| **At v12**    | Migrated components are officially exported from `@carbon/react`. Update your import paths. Codemods are available to automate this.                                                                                                                       |
| **Post-v12**  | `@carbon/ibm-products` enters minimal maintenance mode. Critical bug fixes only — no new features, no new components.                                                                                                                                      |

Every component in this Storybook will be labelled with one of these outcomes:

- **Migrated to `@carbon/react`** — links to the new location and import-path
  change.
- **Deprecated** — Not moving forward due to minimal or no adoption, an existing
  replacement, or because the capability has already been delivered as a
  standard pattern.
- **Moved to Carbon Labs** — available in the community-maintained
  [Carbon Labs](https://github.com/carbon-design-system/carbon-labs) repo.

## What do I need to change?

### Import path change

For every component that migrates to `@carbon/react`, the **only required change
at v12** is the import path:

```jsx
// Before (Carbon v11 / current)
import { SidePanel } from '@carbon/ibm-products';

// After (Carbon v12+)
import { SidePanel } from '@carbon/react';
```

You do **not** need to change how you use the component at v12. The component
API is preserved on migration.

### Preview → Stable components — one-step API migration

Some components were already rewritten as composable previews inside
`@carbon/ibm-products`. Those preview versions are what migrate to
`@carbon/react` and ship as **stable** at v12. For these components, both the
import path **and** the component API change — the old monolithic export is
deprecated.

Migration guides and codemods for each of these will be published alongside the
v12 release.

### Tearsheet, PageHeader and Card — migrate to the composable versions

`Tearsheet`, `PageHeader` and `Card` are being replaced by new composable
implementations. This applies to both the **React** (`@carbon/ibm-products`) and
**Web Components** (`@carbon/ibm-products-web-components`) packages.

| Component  | Current (non-composable) status                                  | New composable version                        | Available in v12  |
| ---------- | ---------------------------------------------------------------- | --------------------------------------------- | ----------------- |
| Tearsheet  | Stable component now carries a **deprecation notice**.           | **Delivered** — available as a **preview**.   | New version only. |
| PageHeader | Stable component now carries a **deprecation notice**.           | **Delivered** — available as a **preview**.   | New version only. |
| Card       | `ExpressiveCard` / `ProductiveCard` will be deprecated **soon**. | **Coming soon** — will ship as a **preview**. | New version only. |

**In v12, only the new composable components will be available.** The existing
stable `Tearsheet`, `PageHeader` and `Card` (`ExpressiveCard`, `ProductiveCard`)
will not be carried forward, so they cannot be used after upgrading.

#### What to do now

- **Start migrating to the new composable versions today.** Do not wait for v12
  — the composable `Tearsheet` and `PageHeader` are already available as
  previews and are the versions that will ship as stable in v12.
- **Treat the deprecation notices as action items.** The old components keep
  working until v12, but will receive no new features.
- **Plan for `Card`.** Avoid starting new work on `ExpressiveCard` or
  `ProductiveCard`. Migrate to the composable `Card` once it is released as a
  preview. This will be released from @carbon/react
- **Expect an API change, not just an import-path change.** The new components
  are composed from smaller building blocks (for example header, body and footer
  parts for `Tearsheet`) rather than configured through a single set of props.

#### React

The composable previews are exported from `@carbon/ibm-products` with a
`preview__` prefix:

```jsx
// Before (deprecated)
import { Tearsheet, PageHeader } from '@carbon/ibm-products';

// After (composable, preview)
import {
  preview__Tearsheet as Tearsheet,
  preview__PageHeader as PageHeader,
} from '@carbon/ibm-products';
```

For codemods, prop mappings and side-by-side examples, see the migration
sections in the component docs:

- [Tearsheet — Migration from Legacy Tearsheet](?path=/docs/preview-tearsheet--docs#migration-from-legacy-tearsheet)
- [PageHeader — Migration guidance from deprecated PageHeader to preview_PageHeader](?path=/docs/preview-pageheader--docs#migration-guidance-from-deprecated-pageheader-to-preview_pageheader)

#### Web Components

Detailed migration guide:
[Tearsheet → `c4p-preview-tearsheet`](https://ibm-products-web-components.carbondesignsystem.com/?path=/docs/preview-tearsheet--docs#migration-from-legacy-tearsheet)

The composable Tearsheet is delivered as a separate set of elements. For
example, use `CDSTearsheetPreview` (`<c4p-preview-tearsheet>`) together with its
companion elements such as `CDSTearsheetHeader`, `CDSTearsheetBody` and
`CDSTearsheetFooter` in place of `CDSTearsheet` (`<c4p-tearsheet>`). Refer to
the `PageHeader` and `Tearsheet` stories for the available composable elements.

Migration guides and codemods will be published alongside the v12 release.
