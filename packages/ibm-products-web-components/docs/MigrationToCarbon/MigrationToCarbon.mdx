## Summary

Starting with **Carbon v12**, the high-value components from
`@carbon/ibm-products-web-components` are being selectively migrated into the
Carbon core packages (`@carbon/web-components`). This means:

- You will eventually install **one package** instead of two.
- Migrated components become first-class Carbon APIs, gaining v12 features
  (updated motion, rounded corners, new tokens) immediately.
- `@carbon/ibm-products-web-components` stays available but enters **minimal
  maintenance mode** after v12 ships — no new features or components will be
  developed there.
- A **one-time import-path change** is required for components that migrate.
  Codemods will be provided to automate this.
- Web Components ports are delivered as follow-up work per component and may not
  land simultaneously with the React implementation at v12. Parity with
  `@carbon/ibm-products` (React) is the target across both flagship packages.

---

## Why is this happening?

`carbon-for-ibm-products` was built upon the foundational components of Carbon
Core, extended with additional components, styling, and guidance crafted
specifically for software product use cases. It is not a replacement for Core,
but a specialized layer on top of it. That separation was useful early on, but
it now creates friction:

- **Two packages to install.** Adopters must manage both `@carbon/web-components`
  and `@carbon/ibm-products-web-components` to get the full component set.
- **Duplicated infrastructure.** Two CI pipelines, two Storybooks, two release
  workflows — maintenance overhead with no consumer benefit.
- **Slower v12 adoption.** Components in a separate repo cannot easily consume
  in-flight monorepo changes, lengthening the feedback loop.
- **Visibility across squads.** PRs and issues from different teams cannot
  cross-reference when work is split across two repos.

## What happens to this package?

| Phase         | What it means for you                                                                                                                                                                                                                                              |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Now → v12** | Everything continues to work. Components are being migrated internally but not yet exported from `@carbon/web-components`. No changes required on your side. Migrated components will be published from release branch (alpha releases) early on with v12 features. |
| **At v12**    | Migrated components are officially exported from `@carbon/web-components`. Update your import paths. Codemods are available to automate this.                                                                                                                      |
| **Post-v12**  | `@carbon/ibm-products-web-components` enters minimal maintenance mode. Critical bug fixes only — no new features, no new components.                                                                                                                               |

Every component in this Storybook will be labelled with one of these outcomes:

- **Migrated to `@carbon/web-components`** — links to the new location and
  import-path change.
- **Deprecated** — Not moving forward due to minimal or no adoption, an existing
  replacement, or because the capability has already been delivered as a standard
  pattern.
- **Moved to Carbon Labs** — available in the community-maintained
  [Carbon Labs](https://github.com/carbon-design-system/carbon-labs) repo.

## What do I need to change?

### Import path change

For every component that migrates to `@carbon/web-components`, the **only
required change at v12** is the import path:

```js
// Before (Carbon v11 / current)
import '@carbon/ibm-products-web-components/es/components/side-panel/index.js';

// After (Carbon v12+)
import '@carbon/web-components/es/components/side-panel/index.js';
```

You do **not** need to change how you use the component (tag names, attributes,
slots, or events) at v12. The component API is preserved on migration.

### Preview → Stable components — one-step API migration

Some components were already rewritten as composable previews inside
`@carbon/ibm-products-web-components`. Those preview versions are what migrate
to `@carbon/web-components` and ship as **stable** at v12. For these components,
both the import path **and** the component API change — the old monolithic
export is deprecated.

| Component          | Change required at v12                                                                                     |
| ------------------ | ---------------------------------------------------------------------------------------------------------- |
| `c4p-tearsheet`    | New import path + migrate to composable API                                                                |
| `c4p-page-header`  | New import path + migrate to composable API                                                                |
| `c4p-condition-builder` | New import path only — API is unchanged                                                               |
| Add and Select     | New import path + migrate to composable system; `c4p-multi-add-select` / `c4p-single-add-select` are deprecated |

Migration guides and codemods for each of these will be published alongside the
v12 release.

### Codemods

Codemods will be published as part of the v12 release to automate import-path
changes. Details will be shared later.
